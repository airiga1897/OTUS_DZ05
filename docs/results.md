# Результаты проверки

Полный цикл выполнен в автоматически выбранном пуле ru-3, сегменте ru-3b,
с SSH/22. [Основной JSON-отчёт](verification-20261020T080521Z.json),
[проверка выбора и сохранения размещения](placement-verification.json) и
[выдержка журнала](verification.log) содержат первичные доказательства.
Дополнительный [отчёт независимого развёртывания](verification-20261019T190833Z.json)
сохранён для проверки воспроизводимости.
Команда повторной проверки — ` .\.tools\venv\Scripts\python.exe scripts/lab.py verify `;
[порядок выполнения](testing.md) описывает условия и ожидаемое поведение.

| Проверка | Проверяемое поведение | Подтверждённый результат |
| --- | --- | --- |
| Кластер | Рабочее большинство и роли | 3 ONLINE, один PRIMARY, два SECONDARY |
| Конфигурация и размещение | Единые настройки, очистка перед сменой пула | Выбран ru-3b, предыдущие попытки очищены; verify/destroy использовали сохранённый пул |
| Django migrate/loaddata | Схема и импорт исходных данных | 4 исходные статьи, PK 1–4, совпали все поля |
| Идентификаторы и права | Целостность идентификаторов и прав | Новый PK 6 выше импортированных; contenttypes, 4 permissions и связи user/group проверены |
| HTTP | Доступность портала | Главная, статья, readiness, CSS — 200 |
| Admin через доверенный SSH | Запись и файловая загрузка через приложение | Вход и создание — 302; чтение статьи и изображения — 200; байты изображения совпали по SHA256 |
| Существующие тесты Django | Совместимость приложения с MySQL | 5 тестов прошли на настоящем MySQL через Router |
| Остановка PRIMARY | Смена узла записи и работа большинства | Оставшиеся два узла ONLINE, выбран новый PRIMARY; запись через приложение подтверждена |
| Readiness при потере PRIMARY | Возобновление запросов после переключения | Зафиксирован краткий 503, затем восстановлен 200 |
| Возврат db1 | Присоединение восстановленного узла | Автоматически ONLINE SECONDARY; три узла ONLINE |
| Остановка SECONDARY | Работа при потере узла чтения | Оставшиеся узлы обслуживали чтение/запись; запись подтверждена; readiness восстановлен |
| Повторное восстановление | Возврат трёх реплик и сохранность данных | Три ONLINE, подтверждённые до остановок записи сохранились |
| Сверка реплик | Одинаковые статьи на репликах | 6 статей на каждом узле, одинаковый SHA256 всех полей; все таблицы InnoDB и с PK |
| Уборка тестовых данных | Возврат к исходным четырём статьям | Удалены временный редактор, группа и статьи; осталось 4 исходных статьи |
| Удаление инфраструктуры | Освобождение ресурсов и прекращение их оплаты | 25 ресурсов удалены; state пуст; API подтвердил отсутствие собственных ресурсов и floating IP |
| SSH/22 | Вход с подтверждённого IPv4 оператора | На отдельной ВМ приложения выполнены вход по ключу, проверка host key и удалённая команда; адрес SSH-клиента совпал с подписанной пробой маршрута и разрешённым /32 |

При смене PRIMARY зафиксирован краткий 503 с последующим восстановлением HTTP 200.
Каждый выключенный узел включается в finally и возвращается в ONLINE.

Дополнительная [проверка SSH/22](ssh-verification.json) подтверждает вход по
ключу с разрешённого адреса оператора. Актуальный [API-аудит](cleanup-latest.json)
относится к полному циклу в ru-3b и подтверждает удаление всех его ресурсов.

Исторических дампов, фикстур и media-архива ДЗ04 не найдено, включая
исключённый из Git локальный каталог: [поиск источника](source-data-search.json).
Четыре статьи восстановлены из seed_lessons исходников ДЗ04, экспортированы
dumpdata и импортированы loaddata. Это восстановление из исходников,
а не перенос исторической PostgreSQL БД. Исходных media — 0;
загрузка и выдача нового изображения проверены отдельно через admin.

Проверенные версии: Ubuntu 24.04.5, MySQL Server/Router 8.0.46,
MySQL Shell 8.0.36, Django 5.2.18, mysqlclient 2.2.7, uWSGI 2.0.31.
Рабочее место повторного запуска: Python 3.14.2, Terraform 1.16.3,
OpenStack provider 3.4.0. [Статус AdminAPI](cluster-status.json),
[cloud-init](cloud-init.json), [финальный API-аудит удаления](cleanup-latest.json).

Граница подтверждённой отказоустойчивости — остановка одной ВМ БД с последующим
восстановлением в одном выбранном сегменте. Приложение, Router и media на одной ВМ —
единая точка отказа. Контрольные суммы сравнивают статьи;
связи пользователей и прав проверены отдельно.
Образ и apt-пакеты могут обновиться при следующем запуске.

Локально прошли 12 тестов защиты конфигурации и выбора пула без облачных запросов.
Команда и назначение приведены в [описании конфигурации](configuration.md).
