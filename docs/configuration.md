# Единая конфигурация и выбор пула

## Где задаются параметры

Единственный редактируемый файл — `.local/lab-config.json`. При подготовке
он копируется из [безопасного примера](../config/lab.example.json).
Python, PowerShell и Terraform используют эти настройки без повторного
задания проекта, пула или адресов в исходном коде.

| Параметр | Назначение |
| --- | --- |
| project_id | UUID своего проекта Selectel; запрашивается при первом вводе credentials |
| pools | Упорядоченный список российских пулов; auto добавляет доступные российские пулы из каталога API |
| segment | Фиксированный сегмент или null для автоматического выбора |
| profiles, flavor_name_template | CPU/RAM ролей и правило поиска подходящих flavors |
| image_name, disk_class, boot_disk_gb | Образ ОС и параметры дисков |
| name_prefix, subnet_cidr, nodes | Имена ресурсов, подсеть и адреса узлов как смещения внутри подсети |
| admin_ssh_port, admin_cidrs | SSH-порт и дополнительные подтверждённые адреса оператора /32 |
| ssh_key_path | Путь к собственной паре ключей внутри .local проекта |
| external_network_name, dns_nameservers | Облачная внешняя сеть и DNS-серверы |

Изменение настроек применяется к следующему новому развёртыванию.
Работающий стенд автоматически не переносится. Префикс должен принадлежать
ДЗ05, адреса внутри подсети должны быть уникальны; роли app/db1/db2/db3
сохраняются. Идентификаторы образа и flavors определяются по каталогу,
тип диска — по выбранному сегменту. Вручную переносить IDs из другого пула
не требуется.

## Credentials и результаты развёртывания

| Файл | Назначение | Редактирование |
| --- | --- | --- |
| .local/lab-config.json | Настройки следующего запуска | Пользователь |
| .local/operator.json | Учётная запись и пароль оператора | Через selectel-env.ps1 / save-operator.ps1 |
| .local/deployment.json | Выбранные проект, пул, сегмент, параметры и связь со state | Только сценарии |
| .local/terraform-inputs.json | Сгенерированные приватные параметры Terraform | Только сценарии |
| .local/lab.json | Адрес портала и UUID ВМ текущего стенда | Только сценарии |
| .local/route-secret.json | Отдельный ключ подтверждения маршрута | Только сценарии |

Все перечисленные файлы исключены из Git. Credentials не задают второй
независимый проект или пул. Для действующего стенда verify/destroy используют
сохранённое размещение и сверяют его с Terraform state. Старый lab.json,
чужой проект/пул и state без контекста отклоняются.

## Выбор размещения

deploy рассматривает кандидатов в порядке pools, проверяет каталоги и
доступные ресурсы. Все четыре ВМ создаются в одном сегменте с тем же составом.
Если Nova подтверждает NoValidHost, сценарий удаляет ресурсы этой попытки,
проверяет пустой state и API-инвентарь и только затем пробует следующего кандидата.
Ошибка очистки блокирует дальнейшие попытки. Ошибки настройки приложения
не запускают подбор другого пула.

При обычном успешном deploy стенд остаётся работать. Для тестового цикла
используется существующий test-cycle с обязательным destroy в finally.
Подробные сведения о кандидатах и предварительных проверках остаются в .local.

## Переход с предыдущей конфигурации

Если старый стенд работает, сначала удалить его скриптами соответствующей
версии и подтвердить очистку. Нельзя создавать новый контекст поверх
непустого state или угадывать пул для удаления.

В подготовленном каталоге без ресурсов перенести пользовательские параметры
из прежнего tfvars в lab-config.json. Старые terraform.tfvars/terraform.tfvars.json
убрать из каталога Terraform в приватный локальный архив: они больше не являются
входными файлами. Затем повторить prepare.py и Terraform init по
[инструкции](operations.md). Сохранённая SSH-пара используется повторно.

## Локальные проверки защиты

Из корня репозитория в PowerShell:

```powershell
.\.tools\venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты выполняются без облачных запросов. Они проверяют отказ от чужих ресурсов,
замены ВМ и устаревшего контекста, неизменность размещения действующего стенда
при редактировании настроек и обязательную очистку перед переходом к следующему
пулу. Эти проверки дополняют живые испытания, не заменяя их.
