# Воспроизводимое выполнение

Управляющая среда: Windows PowerShell, Python 3.12+, Terraform 1.6–1.x,
доступ к Selectel API и внешнему SSH приложения. Внутри ВМ — Ubuntu 24.04.
Terraform управляет инфраструктурой; scripts/node.py, cluster.py и app.py
настраивают ПО. Ansible не требуется: задание допускает скрипты.

## Подготовка нового клона

Установить Terraform из доверенного дистрибутива. Из корня репозитория:

```powershell
.\scripts\setup.ps1 -TerraformPath C:\Tools\terraform.exe
. .\scripts\selectel-env.ps1 -AccountNumber ACCOUNT -ProjectId fdce7ecd9cf742a6a4eda91e927a09fb -UserName OPERATOR -Region ru-9
.\scripts\save-operator.ps1
.\.tools\venv\Scripts\python.exe scripts/prepare.py
.\.tools\venv\Scripts\python.exe scripts/tf.py init '-input=false'
```

prepare.py проверяет текущие image/flavor/SSD каталоги, определяет внешний
IPv4 оператора, генерирует собственную SSH-пару и локальный tfvars.
Существующие tfvars/неполная пара ключей автоматически не перезаписываются.
Если IP изменился, обновить admin_cidrs в собственном tfvars.
HTTPS-проверка внешнего IPv4 может показывать другой адрес, чем исходящий SSH.
В таком случае указать оба подтверждённых адреса отдельными /32, например
через prepare.py --admin-cidr ADDRESS/32 при первом запуске. Допускаются
несколько адресов по примеру локальной конфигурации ДЗ06; реальные адреса
оператора хранятся только в исключённых из Git tfvars.
Перед первым SSH временный HTTP-сервис на ВМ подтверждает адрес прямого
маршрута HMAC-подписью nonce и добавляет только соответствующий /32 в собственную
security group. Сервис выключается до установки Nginx. Одноразовый ключ пробы
не является credentials Selectel; хранится в локальных tfvars/state, исключённых
из Git. Идея пробы переиспользована из ДЗ06, конфигурация и ключ независимы.
Префикс otus-dz05 и подсеть 10.55.0.0/24 не менять для этих сценариев.
Параметры ДЗ06 находятся в другом каталоге и никогда не загружаются.

## Раздельные команды

```powershell
# Создать инфраструктуру, кластер, схему и приложение; оставить для проверки.
.\.tools\venv\Scripts\python.exe scripts/lab.py deploy

# Проверить работающий стенд, остановить/вернуть PRIMARY и SECONDARY ДЗ05.
.\.tools\venv\Scripts\python.exe scripts/lab.py verify

# Удалить только ресурсы собственного state после проверки destroy-плана.
.\.tools\venv\Scripts\python.exe scripts/lab.py destroy
```

deploy повторяет проверку общих квот с резервом для обоих ДЗ. Принимается
только план create/no-op для четырёх ВМ; изменения, замены и чужие имена
отклоняются. Для destroy разрешены delete/no-op только допустимых типов
ресурсов собственного state и имён otus-dz05. После удаления проверяются
пустой state и облачный инвентарь с собственным префиксом.

Для испытаний воспроизводимости использовать автоматический цикл:

```powershell
.\.tools\venv\Scripts\python.exe scripts/lab.py test-cycle
```

Он вызывает deploy → verify → destroy; destroy выполняется в finally также
при ошибке создания, установки или проверки. Ошибка cleanup считается ошибкой
цикла, её нельзя выдавать за успешное удаление. Повторный запуск — только после
проверки текущего state и отсутствия зависшего Terraform-процесса.

## Данные и доступ

Если локального экспорта нет, deploy восстанавливает четыре исходных материала
через миграции SQLite и seed_lessons, затем dumpdata. На MySQL выполняются
настоящие Django migrate и loaddata. Это реконструированные исходные данные,
не исторический перенос удалённой PostgreSQL БД. См. migration.md.

Портал публикует чтение на HTTP/80. Admin проверяется через SSH-туннель.
Внешний SSH по умолчанию TCP/443, ограниченный admin_cidrs; это SSH, не HTTPS.
Внутренний SSH между ВМ использует TCP/22. Для публичного HTTPS следует
назначить SSH отдельный порт и настроить сертификат, это вне учебного стенда.
Router слушает 127.0.0.1:6446; MySQL не имеет публичных IP.

Временный staff-редактор dz05-check с правами Article через группу создаётся для проверки
и удаляется при её успешном завершении. Для своего администратора выполнить
createsuperuser через SSH с окружением /opt/otus-dz05/app.env, без публикации пароля.

## Секреты и журналы

.local/operator.json содержит локальную копию credentials только на время работы;
на ВМ она не передаётся. На ВМ передаются отдельные сгенерированные секреты БД
и приложения. .local, tfvars, state, plans, дампы и SSH-ключи исключены из Git.
При завершении работы локальный operator.json удаляется по поручению пользователя.
Для следующего запуска снова требуется скрытый ввод пароля через selectel-env.ps1.

Полные журналы с техническими адресами сохраняются в .local/terraform.log,
.local/remote.log и локальном stdout цикла. Для сдачи используются только
обезличенные JSON-отчёты и выдержки журналов в docs/.
